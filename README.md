# GPT-5.5 기반 v1·v2 프롬프트 비교 결과보고서

> 과업: 가상회의록을 업무용 회의결과 보고서로 구조화  
> 대상 모델: GPT-5.5  
> 작성일: 2026년 8월 11일  
> 원자료: 「[가상 데이터] 제조기업 현장 지원 AI 에이전트 도입 1차 기획 회의」

## 1. 실험 개요

### 가. 목적

동일한 회의록을 GPT-5.5에 입력했을 때, 간단한 일반 지시인 v1과 요구사항 정리·누락 확인·초안 검증을 유도한 v2의 결과 차이를 비교한다. 비교의 핵심은 장문의 내부 추론 노출 여부가 아니라 최종 산출물의 완전성, 근거성, 실행가능성이다.

### 나. 통제 조건

| 항목 | 적용 조건 |
|---|---|
| 모델 | GPT-5.5 |
| 원문 | 동일한 가상회의록 전문 |
| 과업 | 사내 공유용 회의결과 보고서 작성 |
| 출력 분량 | 1,000자 안팎 |
| 공통 원칙 | 원문에 없는 사실은 만들지 않고, 불명확한 내용은 `미정` 또는 `확인 필요`로 표시 |
| 비교 변수 | 프롬프트의 작업 절차 유도 수준(v1 일반 지시 / v2 단계적 접근) |
| 표시 원칙 | 내부의 상세 추론은 출력하지 않고 요약·근거 중심의 최종 답변만 표시 |

> **실행 기록의 성격:** 아래 결과는 첨부 회의록과 지정 프롬프트를 기준으로 구성한 GPT-5.5 재현용 실행 예시이다. API 원시 로그(응답 ID·토큰·지연시간)를 계측한 실험은 아니므로, 운영 도입 전에는 동일 모델 스냅샷과 동일 파라미터로 반복 평가해야 한다.

```text
김철수: 공장 작업자가 수백 페이지의 설비 매뉴얼을 찾지 않고 대화형
에이전트에게 질문해 즉시 조치하도록 하는 것이 목적이다. 3개월 안에

이영희: 현장이 시끄럽고 작업자가 장갑을 착용하므로 STT가 필수다.

박지민: 설계도면과 공정 노하우가 외부로 유출되면 안 된다. 온프레미스나
프라이빗 클라우드를 고려해야 하며 오답으로 인한 기기 고장의 책임도 정해야 한다.
이영희: 현장 사용을 위해 답변 정확도 99%가 필요하다.
최현우: 모르는 내용은 답하지 않는 정책을 두고, Azure OpenAI 프라이빗
엔드포인트 또는 로컬 LLM을 검토하겠다.
김철수: 다음 주까지 최현우는 기술 스택 비교안, 이영희는 오류 코드 TOP 10,
박지민은 보안 가이드라인 초안을 준비한다.
```

## 3. v1 일반 지시 프롬프트 및 결과

### 가. v1 프롬프트

```text
다음 회의록을 읽고 사내 공유용 회의결과 보고서를 작성해 주세요.

필수 항목: 회의 목적, 주요 논의사항, 결정사항, 담당자별 후속조치,
리스크, 향후 일정

원문에 없는 사실은 만들지 말고, 불명확한 내용은 '확인 필요'로 표시하세요.
최종 답변은 1,000자 안팎의 요약·근거 중심으로 작성하고 불필요한 장문의
추론 과정은 출력하지 마세요.

[회의록]
{{공통 입력 전문}}
```

### 나. v1 결과

#### 제조기업 현장 지원 AI 에이전트 도입 1차 기획 회의 결과

- **목적:** 작업자가 설비 매뉴얼을 직접 검색하지 않고 대화형 AI를 통해 오류 조치 정보를 신속히 확인할 수 있는 파일럿을 3개월 내 구축한다.
- **주요 요구사항:** 소음 환경과 장갑 착용을 고려한 STT, 오류 코드별 즉시 답변, 매뉴얼 PDF 기반 RAG, 제조 전문용어·사내 약어 대응이 필요하다.
- **보안·안전:** 설계도면과 공정 노하우의 외부 유출을 방지하기 위해 온프레미스 또는 프라이빗 클라우드를 검토한다. 환각 방지를 위해 근거가 없으면 답변하지 않는 정책을 적용한다. 목표 정확도는 99%이다.
- **기술 검토안:** Azure OpenAI 프라이빗 엔드포인트와 로컬 LLM을 비교한다.
- **후속조치:** 최현우 대리는 기술 스택 비교안, 이영희 과장은 빈발 오류 코드 TOP 10, 박지민 책임은 보안 가이드라인 초안을 다음 주까지 준비한다.
- **리스크:** 음성인식 성능 저하, 전문용어 인식 오류, AI 오답에 따른 설비 고장, 데이터 유출 위험이 있다.
- **향후 일정:** 다음 주 자료 취합 후 기술·보안 방식을 검토하고 3개월 내 파일럿 테스트를 완료한다.

### 다. v1 관찰

v1도 회의 목적과 명시된 후속조치를 비교적 정확히 요약했다. 그러나 ‘결정된 사항’과 ‘검토 후보’를 구분하지 않았고, 99%가 측정 정의 없는 이해관계자 요구라는 점, 책임체계·평가방법·중간 마일스톤이 미정이라는 점을 명시하지 않았다. 마지막 문장의 ‘다음 주 자료 취합 후 검토’는 자연스러운 추론이지만 회의록의 명시적 결정은 아니다.

## 4. v2 단계적 접근 프롬프트 및 결과

### 가. v2 프롬프트

```text
다음 회의록을 사내 공유용 회의결과 보고서로 정리하세요.

[작업 절차]
1. 먼저 원문에서 목적·기한·요구사항·결정사항·검토사항·담당자·리스크를 구분한다.
2. 보고서 작성에 필요한 정보가 누락되었는지 점검한다. 사용자에게 즉시
   질문할 수 없는 상황이므로 누락 항목은 추측하지 말고 '확인 필요'로 표시한다.
3. 원문의 발언으로 확인되는 내용만 사용해 초안을 작성한다.
4. 최종 제출 전 다음을 자체 점검한다.
   - 결정사항과 제안·검토사항을 혼동하지 않았는가?
   - 담당자·산출물·기한을 정확히 연결했는가?
   - 수치 목표에 측정기준이 있는가?
   - 원문에 없는 일정·책임·기술 결론을 추가하지 않았는가?

[최종 출력 형식]
① 회의 개요 ② 확정사항 ③ 핵심 요구사항 ④ 검토 필요사항
⑤ 실행계획 표(담당자/산출물/기한) ⑥ 주요 리스크 및 대응 원칙
⑦ 확인 필요사항

[출력 규칙]
- 최종 답변은 1,000자 안팎의 요약·근거 중심으로 작성한다.
- 위 작업 절차의 상세 추론이나 내부 검토 과정은 출력하지 않는다.
- 근거가 없는 내용은 생성하지 않고 '확인 필요'로 표시한다.

[회의록]
{{공통 입력 전문}}
```

### 나. v2 결과

#### ① 회의 개요

2024년 5월 22일, 제조현장 작업자가 설비 매뉴얼을 직접 찾지 않고 대화형 AI로 조치 정보를 확인하는 파일럿 도입 방안을 논의했다. 목표 시점은 회의일로부터 3개월 이내이다.

#### ② 확정사항

- 최현우 대리, 이영희 과장, 박지민 책임이 각 지정 자료를 다음 주까지 준비한다.
- 근거가 부족한 질문에는 답변하지 않는 안전장치를 적용하는 방향으로 추진한다.

#### ③ 핵심 요구사항

- 소음·장갑 착용 환경을 고려한 STT
- E-0402 등 오류 코드의 신속한 조치 안내
- 매뉴얼 PDF 기반 RAG와 제조용어·사내 약어 대응
- 설계도면·공정 노하우의 외부 유출 방지
- 현장 요구 목표 정확도 99%

#### ④ 검토 필요사항

Azure OpenAI 프라이빗 엔드포인트와 로컬 LLM은 확정 기술이 아니라 비교 대상이다. 온프레미스와 프라이빗 클라우드의 보안성·비용·운영성을 함께 검토해야 한다.

#### ⑤ 실행계획

| 담당자 | 산출물 | 기한 |
|---|---|---|
| 최현우 대리 | 기술 스택 비교안 | 다음 주까지 |
| 이영희 과장 | 빈발 오류 코드 TOP 10 | 다음 주까지 |
| 박지민 책임 | 보안 가이드라인 초안 | 다음 주까지 |

#### ⑥ 주요 리스크 및 대응 원칙

데이터 유출, STT·전문용어 인식 오류, 환각에 따른 잘못된 조치와 설비 손상이 핵심 위험이다. 답변 근거 제시, 저신뢰 답변 거부, 권한·접근통제, 파일럿 검증을 기본 원칙으로 삼되 구체 기준은 추가 합의가 필요하다.

#### ⑦ 확인 필요사항

99% 정확도의 정의·평가 데이터·합격기준, 오답 발생 시 책임·승인체계, 파일럿 범위와 중간 일정, 예산, STT 성능 기준은 회의록에 없다. ‘다음 주’의 정확한 제출일도 확인해야 한다.

### 다. v2 관찰

v2는 원문의 사실을 ‘확정·요구·검토·미정’으로 분리했다. 특히 기술 후보를 확정안으로 오인하지 않았고, 실행계획의 담당자·산출물·기한을 표로 연결했으며, 99% 목표의 측정기준 부재와 책임체계 등 누락 정보를 드러냈다. 다만 절차 지시가 길어 입력 토큰과 작성 시간이 늘어날 수 있다.

## 5. 결과 비교 및 평가

### 가. 평가 기준

5점 척도를 사용했다. 평가는 원문 대조에 의한 정성 채점이며, 각 점수의 근거를 함께 기록했다.

| 평가 항목 | 가중치 | v1 | v2 | 판단 근거 |
|---|---:|---:|---:|---|
| 사실 정확성·근거 충실성 | 25% | 4.0 | 5.0 | v2가 확정안과 검토 후보를 명확히 분리 |
| 요구사항·누락 탐지 | 20% | 3.0 | 5.0 | v2가 정확도 정의, 책임, 예산, 범위 등의 부재를 표시 |
| 실행계획 명확성 | 20% | 4.0 | 5.0 | v2가 담당자·산출물·기한을 표로 연결 |
| 리스크·통제 관점 | 15% | 3.5 | 4.5 | v2가 저신뢰 답변 거부와 확인 필요사항을 연결 |
| 형식·가독성 | 10% | 4.0 | 4.5 | v2의 정보 계층이 더 명확함 |
| 간결성·효율성 | 10% | 5.0 | 4.0 | v1의 프롬프트가 더 짧고 단순함 |
| **가중 총점** | **100%** | **3.78/5 (75.5점)** | **4.75/5 (95.0점)** | **v2가 19.5점 우위** |

### 나. 해석

v1은 빠른 1차 요약에 적합하지만, 복합 회의록에서는 결정·제안·미정 사항을 섞을 가능성이 있다. v2는 작성 전에 정보 유형을 분류하고 누락을 확인하도록 하여, 회의 후속조치와 리스크가 중요한 제조·안전 업무에서 더 안정적인 산출물을 만든다. 다만 이 결과는 1개 회의록에 대한 예시이므로 일반화하려면 복수 회의록과 반복 실행이 필요하다.

## 6. GPT-5.5 선택 근거

### 가. 과업 적합성

1. 회의록 요약은 발언에서 요구사항·결정·리스크·담당자 관계를 분리하는 다단계 전문 업무이다. GPT-5.5는 내부 reasoning token을 사용하는 추론 모델로, 공식 문서상 계획, 대안 검토, 모호성 처리와 복수 단계 업무에 적합하다.
2. 공식 모델 문서는 GPT-5.5를 복잡한 전문 업무용 frontier 모델로 설명하며, 구조화 출력과 대규모 문맥을 지원한다. 따라서 긴 회의록의 문맥 유지와 일정한 보고서 형식 준수에 적합하다.
3. 본 실험은 모델 성능 순위 결정이 아니라 v1·v2 프롬프트 설계 효과 비교가 목적이다. 동일한 고성능 모델로 통제하면 결과 차이를 프롬프트 구조의 영향으로 해석하기 쉽다.

### 나. 한계와 운영상 유의점

- GPT-5.5의 선택 근거는 ‘이 과업에 적합함’이지 ‘현재 모든 모델 중 항상 최적’이라는 의미가 아니다. 공식 문서에는 이후 세대 모델도 안내되어 있으므로 실제 도입 시 품질·지연·비용을 대표 데이터로 재평가해야 한다.
- GPT-5.5는 텍스트 입출력을 지원하지만 오디오 입력을 직접 지원하지 않는다. 회의에서 요구한 현장 STT는 별도의 음성인식 구성요소와 연계해야 한다.
- 제조 안전 분야에서는 모델 자체의 유창함이 정답성을 보장하지 않는다. RAG 근거, 답변 거부 임계치, 사람 승인, 현장 검증을 함께 설계해야 한다.

공식 근거: [GPT-5.5 모델 사양](https://developers.openai.com/api/docs/models/gpt-5.5), [추론 모델 안내](https://developers.openai.com/api/docs/guides/reasoning)

## 7. 결론 및 권고

최종 채택안은 **v2 단계적 접근 프롬프트**이다. 동일 회의록에서 v2는 v1보다 결정사항과 검토사항의 경계를 명확히 하고, 담당자별 실행계획과 누락 정보를 더 완전하게 제시했다. 특히 제조현장 AI처럼 보안·안전·책임이 중요한 과업에서는 단순 요약보다 ‘분류 → 누락 점검 → 근거 기반 작성 → 최종 검증’ 구조가 적합하다.

실무 적용 시에는 v2를 표준 템플릿으로 사용하되, 다음 조건을 권고한다.

1. 동일 GPT-5.5 스냅샷과 파라미터를 고정한다.
2. 최소 10개 이상의 서로 다른 회의록에 대해 각 버전을 3회 이상 반복 실행한다.
3. 사실오류, 누락률, 결정·검토 오분류율, 담당자 연결 정확도, 작성시간·토큰을 계측한다.
4. 최종 보고서는 원문 근거를 사람이 확인한 뒤 배포한다.
